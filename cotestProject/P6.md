## 总述
CPU 为的 5 级流水线阶段为：

| 阶段                  | 简称 | 功能概述                                               |
| --------------------- | ---- | ------------------------------------------------------ |
| 取指阶段（Fetch）     | F    | 从指令存储器中读取指令                                 |
| 译码阶段（Decode）    | D    | 从寄存器文件中读取源操作数并对指令译码以便得到控制信号 |
| 执行阶段（Execute）   | E    | 使用 ALU 执行计算                                      |
| 存储阶段（Memory）    | M    | 读或写数据存储器                                       |
| 写回阶段（Writeback） | W    | 将结果写回到寄存器文件                                 |

## 思考题

### 1. 为什么需要有单独的乘法部件而不是整合进ALU？为何需要有独立的HI、LO寄存器？
乘法除法运算时间较长，与ALU分开可以使得ALU并行进行运算，加快处理效率。独立的HI LO寄存器同样方便时间较长的运算直接存储，不需要使整个CPU等待


### 2. 真实的流水线CPU是如何使用实现乘除法的？请查阅相关资料进行简单说明。
乘法除法通过加法移位，每个周期计算若干位的结果，在一定周期后得出结果。除法也是通过迁移求部分和，累减实现，对齐余数和除数后再相减，一个周期完成若干位计算即可。


### 3. 请结合自己的实验分析，你是如何处理Busy信号带来的周期阻塞的？
当 D 级指令是 8 条乘除法指令，且 start 信号或 busy 信号为 1 时，直接阻塞


### 4. 请问采用字节使能信号的方式处理写指令有什么好处？（提示：从清晰性、统一性角度考虑）
字节使能信号可以根据1/0情况直接确定写入内存的位置，同时不论何种存储都可以通过字节使能信号进行控制，控制方法统一，且更容易和mips_tb衔接从而进行测试


### 5.请思考，我们在按字节读和按字节写时，实际从 DM 获得的数据和向 DM 写入的数据是否是一字节？在什么情况下我们按字节读和按字节写的效率会高于按字读和按字写呢？
在实现了字节使能信号之后，我们和DM进行的数据交流均以字为基本单位，而非一字节，DM在获取使能信号后还需要进一步对该信号的解析，这反而降低了按字节读写的效率，当不支持按字写时，按字节写的效率要高于按字写。
当我们只需要对字节或半字访问时，按字节访问内存性能更由优势。如果此时还采用按字访问，则需要首先将整个字从内存中拿出来，然后再从字中寻找，效率会更低。


### 6. 为了对抗复杂性你采取了哪些抽象和规范手段？这些手段在译码和处理数据冲突的时候有什么样的特点与帮助？
尽量不在主模块上进行操作，为控制信号留出充足的位宽，减少无效控制信号的数量，这样每个模块只需要根据控制信号按照自己的方式进行处理，根据AT相关数值判断数据冲突。

### 7. 在本实验中你遇到了哪些不同指令组合产生的“冲突”？你又是如何解决的？相应的测试样例是什么样的？
与P5相比，仅仅增加了两种冲突，一种是乘除法内部冲突，即乘除模块还未运算出结果并写进hi与lo，便用mfhi指令调用了寄存器。另一种是mflo与mfhi还未将值存进寄存器就需要使用相关寄存器的值。
对于第一种冲突，在Busy信号为1且需要使用乘除法模块时阻塞。对于第二种冲突，将T_new置为1并进行转发，测试样例如下：
